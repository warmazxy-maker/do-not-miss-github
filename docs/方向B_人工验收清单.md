## 1. B1：推荐和主动反馈

窗口 A 用学生账号登录，进入“事件”页，用 AI 搜索。

- [ ] 搜“想找能练 Java 后端的实践机会”：
  - 推荐里应该有 Spring Boot 工作坊、Java 后端实习这类活动；
  - 每张推荐卡片上有“感兴趣”“不相关”两个按钮。
- [ ] 对一个推荐点“感兴趣”：提示“已记录：感兴趣”。
- [ ] 对另一个推荐点“不相关”，填原因，比如“我不想参加线上活动”：
  - 提示“之后不会再推荐这个活动”；
  - 按钮变成“已标记不相关 · 撤销”。
- [ ] 等一分钟，用**同样的话**再搜一次：刚才标了不相关的活动**不再出现**。
- [ ] 点“撤销”，再搜一次：它可以重新出现（排不排进前几名由模型决定，不出现不算错）。最后再把它标回“不相关”，第 5 步要用。
- [ ] 再搜两三个不同的需求，比如“想练日语口语”“周末能做的志愿活动”“有报酬的短期工作”，让后面的统计有数据。

## 2. B1：隐式反馈（推荐后 7 天内的动作）

- [ ] 在推荐结果里**预约**一个活动，再**取消**；然后再预约另一个。
- [ ] 关注一个推荐活动的组织。
- [ ] 窗口 B 用这个活动所属的组织账号登录，在“我的事件”里点“签到”，粘贴学生“我的预约”里的签到凭证：显示“签到成功”。

这些动作会算作这次推荐收到的反馈，第 4 步在面板上核对。

## 3. B3：反馈进入画像

画像在后台异步更新，前端没有直接显示画像的地方，所以从两个侧面看。

- [ ] 窗口 B 改用 admin_zero 登录，打开运维面板“Agent 运行”：能看到刚才反馈之后出现的**画像刷新**运行，状态是成功。打开看产物，能看到“接受 / 拒绝”的归纳。
- [ ] 回到学生窗口，搜一个宽泛的需求，比如“推荐一些适合我的活动”：结果应该倾向你点过“感兴趣”的类型，避开你说过不想要的类型（比如线上活动）。

第二项是主观判断，模型不一定每次都体现。只要第一项的归纳内容对，就算通过。

## 4. B2：运维面板“推荐”分区

用 admin_zero 打开运维面板“推荐”分区。

- [ ] 推荐次数和你刚才搜的次数大致一致。
- [ ] 零结果率明显低于之前的 42.9%（那时线上只有 1 个没过期的活动）。
- [ ] 反馈漏斗：曝光数，以及感兴趣、不相关、预约、完成、关注的数量和比率，和你的操作对得上。取消预约记为取消，不算预约。
- [ ] “不相关原因”里能看到你填的原因。
- [ ] “最近推荐”里能看到你的每次推荐和它收到的反馈；点一条能跳到那次推荐的 Agent 运行记录。

## 5. B4：差评转评测用例

窗口 B 改用运营账号登录，进入运营后台“评测候选”。

- [ ] 第 1 步标“不相关”的那次推荐，自动生成了一条**待审核**的候选，内容包括学生当时的需求、被推荐的活动和原因。
- [ ] 改写需求，去掉里面的个人信息，然后点“采纳”：状态变成“已采纳”。
- [ ] 再拒绝一条（如果有第二条）：状态变成“已拒绝”。
- [ ] 点“生成下一版评测集”：显示新的评测集版本号（比如 `retrieval-eval-v2`）和语料版本号。文件要由开发者提交，页面上会说明。
- [ ] 运营这里**没有**“看那次推荐”的链接（那个链接跳到运维面板，运营没有权限）。用 admin_zero 在运维面板看同一条候选：有这个链接。
- [ ] 回到学生窗口，撤销那条“不相关”：已经采纳的候选**不受影响**，仍是“已采纳”。
