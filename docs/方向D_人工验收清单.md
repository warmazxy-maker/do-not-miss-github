# 方向 D 人工验收清单

> 2026-11-03 整理。覆盖 D1 权限、D2 活动生命周期、D3 运营后台、D4 限流。D0 已被 D1 取代，不单独验收。
> 按顺序做，后面的步骤会用到前面建好的账号和活动。每一项后面写着**应该看到什么**；不一致就在“问题记录”里记一笔，不用当场排查。
> 全程大约 40～60 分钟。会真的调用模型（AI 审核、AI 搜索），大约几十次调用。

---

## 0. 准备

- [ ] 打开 Docker Desktop，等 MySQL、Redis、RabbitMQ 都显示 healthy。
- [ ] **重启后端**：之前开着的后端是旧代码，必须重启才有 D3、D4。启动日志里应该能看到 `Schema ... is up to date`（V34 已经执行过）。
- [ ] 启动前端（`npm run dev`）。
- [ ] 准备**两个互不干扰的浏览器窗口**，比如一个普通窗口、一个无痕窗口，或者两个不同的浏览器。登录信息存在浏览器里，同一个窗口只能登一个账号。后面需要同时登录组织和运营。

本次要用到的账号：

| 角色 | 怎么来 |
|---|---|
| 超级管理员 | `admin_zero`，密码是本地 `.env` 里的 `ADMIN_ZERO_PASSWORD` |
| 运营 | 第 2 步由 admin_zero 新建 |
| 组织 | 第 1 步自己注册，比如 `test_org` |
| 学生 | 第 1 步自己注册，比如 `test_stu` |

## 1. D1：注册和角色

- [ ] 打开注册页：角色只能选**学生**或**组织**，没有运营或管理员。
- [ ] 注册一个组织账号和一个学生账号。
- [ ] 组织登录后自动进入“我的事件”，学生登录后自动进入“事件”。
- [ ] 学生在地址栏直接输入 `/ops` 和 `/operator`：两个都进不去。
- [ ] 学生登录状态下，在地址栏输入 `/social/publish`：也进不去。

---

## 2. D3：admin_zero 建运营账号

窗口 A 用 admin_zero 登录。

- [ ] 登录后自动进入运维面板 `/ops`。
- [ ] 分区里有“审计日志”“限流”“运营账号”。
- [ ] 打开“运营账号”，新建一个运营账号，比如 `test_op`：
  - 页面显示一个 16 位初始密码，**只显示这一次**，先复制下来；
  - 刷新页面后，列表里有这个账号，但看不到密码。
- [ ] 再用同一个用户名新建一次：提示用户名已存在。
- [ ] 打开“审计日志”：能看到刚才“新建运营账号”成功和失败的两条记录。（第 1 步学生进不去 `/ops` 是前端路由挡的，请求没到后端，所以这里不会有记录。）
- [ ] 运维面板顶部有“运营后台”入口，点进去能打开 `/operator`。

---

## 3. D2：组织端的活动生命周期

窗口 B 用组织账号登录。

### 3.1 草稿
- [ ] 进入“发布事件”，填好一个**内容完整**的活动（开始时间填未来），点**只保存不提交**：
  - “我的事件”里出现这个活动，状态是“已保存”；
  - 有“编辑”“提交审核”“放弃”按钮。
- [ ] 点“编辑”改个标题，保存：状态仍是“已保存”。

### 3.2 提交给 AI 审核
- [ ] 点“提交审核”：状态变成“审核中”。
- [ ] 稍等十几秒刷新：AI 审完后状态变成“已上架”，或者“需修改”并附带修改意见。
- [ ] 打开这个活动的**状态历史**：每一步都有记录，写着是谁做的（组织 / AI 审核）。

### 3.3 需修改
再发布一个**故意很简陋**的活动（比如正文只写“来玩”），提交审核。

- [ ] AI 给出“需修改”，并在“我的事件”里显示修改意见。
- [ ] 按原样（仍然简陋）再提交，重复到 **AI 一共要求修改 3 次**。
- [ ] 第 4 次提交后：状态是“审核中”，但这次**不再等 AI**，而是进入人工审核队列（第 5 步会看到）。
- [ ] 先**不要**打开“我的事件”之外的页面，记住这个活动，第 5 步要用。

### 3.4 下架和放弃
- [ ] 对一个“已上架”的活动点“下架”：**必须填原因**才能下架；下架后状态是“已下架”，没有“重新上架”按钮（只有运营能重新上架）。
- [ ] 对一个“已保存”的草稿点“放弃”：它从列表里消失。

---

## 4. D2：学生预约和组织签到

窗口 A 退出 admin_zero，改用学生账号登录。

- [ ] 在“事件”里能搜到组织那个“已上架”的活动，预约它。
- [ ] “我的预约”里能看到它，点“签到凭证”能看到一串 token，可以复制。
- [ ] 在窗口 B（组织）的“我的事件”里点这个活动的“签到”，粘贴学生的 token：显示“签到成功”。
- [ ] 学生的“个人成就”里出现这条经历（异步处理，可能要等几十秒再刷新）。
- [ ] 再发布一个活动，让 AI 通过、学生预约，然后由组织下架：学生的“我的预约”里**预约还在**，但醒目提示活动已下架。

---

## 5. D3：运营后台

窗口 A 退出学生，用第 2 步的运营账号和初始密码登录。

### 5.1 入口和权限
- [ ] 登录后自动进入运营后台 `/operator`，有“审核队列”“活动管理”“评测候选”三个分区。
- [ ] 在地址栏输入 `/ops`：进不去（运维面板只给管理员）。

### 5.2 审核队列
- [ ] 第 3.3 步那个转人工的活动出现在队列里，标着“转人工”，并显示等了多久。
- [ ] 点开详情，能看到：
  - 活动的完整信息；
  - 最新一份 AI 报告；
  - **AI 历次要求修改的理由**（应该有 3 条）；
  - 完整的状态历史。
- [ ] 点“要求修改”：**必须填原因**。提交后它从队列里消失。
- [ ] 在窗口 B（组织）：侧边栏“我的事件”上出现**小红点**；打开“我的事件”能看到运营写的修改意见，小红点消失。
- [ ] 组织再提交一次：它又出现在运营的队列里（仍是转人工）。这次点“通过”：组织那边状态变成“已上架”。

### 5.3 抽检
- [ ] 点“抽检”：从最近 AI 通过的活动里抽出几个，标着“抽检”，出现在同一个队列里。如果抽到 0 个，说明还没有 D2 之后被 AI 通过的活动，可以先回第 3.2 步再让 AI 通过一个。
- [ ] 抽检期间，学生在“事件”里**仍然能看到**这个活动。
- [ ] 对一个抽检点“没问题”：它从队列里消失，活动不受影响。
- [ ] 再抽一次，对另一个点“有问题，下架”并填原因：活动被下架，组织那边出现小红点和下架原因。
- [ ] 再点“抽检”：抽过的活动**不会再被抽到**。

### 5.4 活动管理
- [ ] 按状态筛选“已下架”：能看到刚才下架的活动，以及 D2 迁移时转成“已下架（活动已结束）”的旧活动。
- [ ] 打开一个被下架、还没结束的活动，点“重新上架”：状态变回“已上架”。
- [ ] 打开一个“审核中”或“需修改”的活动：有“交回 AI 重新审核”按钮。

### 5.5 两个人同时处理同一个活动
- [ ] 窗口 B 退出组织，用 admin_zero 登录，从运维面板进入运营后台。
- [ ] 两个窗口打开**同一个**待处理的活动详情，先在窗口 A 点“通过”，再在窗口 B 点“要求修改”：窗口 B 提示“数据已被其他人修改”，并自动刷新出最新状态。

### 5.6 评测候选
- [ ] 打开“评测候选”：能看到列表（如果之前在推荐上点过“不相关”）。运营这里**没有**“看那次推荐”的链接。

## 6. D4：限流

### 6.1 AI 接口
窗口 A 用学生账号登录。

- [ ] 在“事件”页用 AI 搜索 / 推荐，**一分钟内连续搜 4 次**：前 3 次正常，第 4 次提示类似“重 AI 功能太频繁（每分钟最多 3 次），请 XX 秒后再试”。
- [ ] 等提示里的秒数过去，再搜一次：恢复正常。

### 6.2 登录锁定
用一个**不重要的账号**，比如再注册一个 `test_lock`，因为它会被锁 15 分钟。

- [ ] 退出后用这个账号输错密码 4 次：每次提示“账号或密码错误”。
- [ ] 第 5 次输错：提示“密码连续输错 5 次，请 15 分钟后再试”。
- [ ] 这时**输对密码**也登不进去，提示同样的话。
- [ ] 换一个账号（比如学生账号）用正确密码登录：正常登录，不受影响。

### 6.3 运维面板
用 admin_zero 打开运维面板。

- [ ] 进入“限流”分区，能看到：
  - 今天的模型调用次数（对话和向量分开），不是 0；
  - 预算条（默认 2000）；
  - 今天被限流的次数：至少有“重 AI 功能”和“登录锁定”各 1 次；
  - 被限流最多的对象：能看到学生的用户名和一个 IP。
- [ ] “Redis / 数据库”分区的键空间里，能看到 `rl:*` 和 `ai:calls:*` 两类键。

---

## 7. 不用测的部分（已有单测或做不到）

- 每天的额度（每天 30 次、组织每天提交 20 次）：要等一整天，单测已覆盖。
- AI 并发闸（同时最多 2 个）：要同时发出 3 个很慢的请求，手工很难做，单测已覆盖。
- 注册每 IP 每小时 5 个：会妨碍后面注册测试账号，脚本已验证过。
- 不同 IP 不受登录锁影响：本地只有一个 IP，单测已覆盖。
