# 方向 F：总控 Agent（Master）

> 2026-11-12 商定方向。这份文档只列阶段和每个阶段要讨论的问题；每个阶段开工前单独讨论设计，再动手。

## 已定

| # | 决定 |
|---|---|
| 1 | 总控新建，和“教练”**并存**。教练原样保留，以后再考虑它的定位。 |
| 2 | 主动性：通过**站内收件箱**留言。收件箱本身也做成总控的一个工具。不做邮件和推送。 |
| 3 | 会改动数据的操作（加日程、建挑战、预约、改目标……）**一律由学生在卡片上点确认**后才执行。 |

| 6 | 成本由开发者先定一个保守值，以后看运维面板的数据再调。 |

## 设计原则（讨论里已经说过的）

- **总控负责“和人打交道”，不负责“打分”。**活动审核、能力评分、简历定段这些流程保持原样，总控只把它们当工具调用或读取结果。
- **“盯着用户”靠事件叫醒，不靠模型一直轮询。**什么时候叫醒由 Java 按业务事件决定（签到成功、写了心得、晋级、活动明天开始、每日例行检查）；叫醒后说什么、做什么由模型决定。
- **工具以学生本人的身份执行**，沿用 D1 的权限；工具的结果作为数据交给模型，不当作指令。
- **每一轮都留痕**：每次对话、每次工具调用都记进现有的 Agent 运行记录，运维面板可以查。

### F0：工具注册表与协议（已完成，2026-11-12）

> 实现说明见 `func_report/F0_工具注册表与调用协议.md`。运维面板的两个新分区待人工验收。

- **工具定义放在代码里，作为唯一的来源。**每个工具是一个实现统一接口的 Java 类，登记这些信息：
  - 名称、版本；
  - 给模型看的描述；
  - 参数的 JSON Schema；
  - 风险等级：只读 / 建议 / 写入 / 内部；
  - 属于哪些 Agent；
  - 需要什么权限；
  - 走哪个限流档；
  - 是否启用。
- 启动时自动收集成注册表，检查名称不重复、Schema 合法；运维面板可以查看这张表。
- **统一调用协议**：内部有一套自己的“调用请求 / 调用结果”格式，再分别转换成模型接口要的格式，以后也可以转成 MCP 的格式。这样换模型、对外开放都不用改工具本身。
- 模型客户端支持原生工具调用。开工前先做小实验，验证现在用的模型接口在工具调用上稳不稳定，不稳定就退回“JSON 选动作”的方式，协议不变。
- Agent 循环：每轮工具调用的步数有上限，单个工具有超时；工具出错会把错误告诉模型，不会让整轮对话直接崩掉。

**F0 已定（2026-11-12）：**
1. 工具定义只放在代码里，不建数据库表；运维面板只读展示。
2. 由 Agent 登记它能用哪些工具（白名单），另有 Agent 注册表：名称、提示词版本、工具白名单、每轮步数上限、限流档。
3. 风险用“维度”表示，第一版两个维度：是否改数据（只读 / 需确认写入 / 内部写入）× 是否调用模型。结构上留出以后加新维度的空间。
4. 协议：请求带工具名、参数、调用编号，以及系统填写的调用方（用户、Agent、运行编号），用户 ID 永远不是参数；结果有四种状态（成功 / 出错 / 无权限 / 等待确认），分别给模型一份、给用户一句话。
5. 每轮最多 6 步；单个工具超时 15 秒（会调模型的 30 秒）；一轮总共 60 秒；只读工具并行执行。
6. 工具出错或降级时，**必须如实告诉学生，用平常的话说**，不能悄悄跳过；同时记进运行记录。
7. 返回结果只做**字段裁剪**（去掉无用字段、超长文本截断），不在语义上删减内容。有边界的数据全量返回；没有边界的查询（比如历史记录），由工具参数要求必须带范围或分页，范围不清楚时模型先问学生。另有一个结构上的安全上限，触发时结果里写明“只返回了前 N 条，共 M 条”，模型必须如实转告。
8. 验收：运维面板的“工具”分区，加上只有管理员能用的调试台。

### F1：总控对话和只读工具（已完成，2026-11-13）

> 实现说明见 `func_report/F1_Tandem对话与记忆.md`。页面待人工验收。

- 新页面“总控”（名字待定），和教练并列。
- 第一批只读工具：画像、能力档案、预约、日程、挑战、成就历史、关注的组织。
- 一个建议类工具：搜活动，复用现有的导购和检索。
- 总控的记忆：
  - 当前对话的短期记忆；
  - 跨对话的长期摘要；
  - 读取用户画像快照。

**F1 已定（2026-11-13，部分）：**
1. 每个学生和总控只有一条长对话，不分会话。
2. 记忆分四层：对话原文、工作记忆（最近消息加滚动摘要）、长期记忆、背景（画像快照）。**长期记忆只存关键事实**：活动、预约、简历、能力这些工具查得到的东西不存。学生能看到、删除长期记忆。
3. 不读教练的记忆。教练冻结，以后可能删掉，功能并入总控。
4. 历史里不保留旧的工具原始数据，只保留“查了什么、查到几条”的摘要；需要时重新查。
5. 等待时显示类似任务清单的进度，执行到哪一步就显示到哪一步（SSE 推送进度）。
6. 新增 4 个工具：搜活动、看活动详情、查关注的组织、查偏好画像。“不调用模型”是指工具本身不额外调用模型；总控始终知道自己调了哪些工具、拿到了什么结果。
7. 人设：伙伴，不是老师；不做心理咨询；诚实。
8. “Agent 对话”限流放宽到每分钟 8 次、每天 80 次。
9. 提供“清空对话”，长期记忆不受影响。

10. 页面名字：**Tandem**（代码里仍叫 master）。
11. 长期记忆：5 类（个人情况、约束、偏好和反感、意向、约定），最多 50 条，同一件事更新原条，可以设有效期，学生能删。
12. 进度清单边做边长。
13. 简历工具等新的简历功能设计好后再加。

14. 一轮的时间上限从 60 秒放宽到 90 秒，搜活动单个工具 60 秒（2026-11-13）。

### F2：确认卡片和写入类工具

- 写入类工具不会直接执行，而是先生成一条“待确认操作”，前端显示成卡片，学生点确认后才真正调用现有的服务。
- 待确认操作有过期时间，重复点击不会重复执行。
- 第一批写入工具：加日程、建挑战、预约活动。

**已定（2026-11-20 讨论，已实现，见 `func_report/F2_确认卡片与写入工具.md`）：**
1. 出卡片后模型照常说完，这一轮结束；点按钮后不叫醒 Tandem，下一轮通过系统记录知道每张卡片的状态。
2. 第一批：加日程、改日程、建挑战、预约活动；删除和取消类操作不交给 Tandem。
3. 每件事一张卡片，几张卡片同时出现时可以“全部确认”。
4. 卡片显示类型、关键信息、影响和冲突提醒（只提醒不拦）；卡片上不能改，要改就出新卡片（`replaces_card`），旧的作废。
5. 两遍检查：出卡片时检查一遍，做不了就不出；确认时现有服务再检查一遍。
6. 24 小时过期，清空对话时作废未确认的卡片。
7. **版本回滚**（你的决定）：模型能改数据就必须能回滚。每个写入工具都必须实现回滚；只回滚这一次做的事；结果被手动改过就拒绝回滚。
8. 状态机加带条件的 UPDATE，状态变化和业务写入放在同一个事务里，点几次都只执行一次。
9. 提出、确认、取消、过期、撤销都记进运行记录，F5 用来统计采纳率和撤销率。
10. 只认按钮；卡片内容由后端从数据库生成，确认时执行冻结的参数，不再经过模型。

### F3：目标

- 目标的数据模型：
  - 目标本身；
  - 拆出来的阶段性里程碑；
  - 关联的能力桶；
  - 状态。
- 总控负责和学生一起设定、拆解、定期回顾；创建或修改目标要走确认卡片。
- 目标进度只在总控页显示，不改个人成就页（已定第 4 条）。

**要和你讨论的：**
- 目标是自由文字，还是关联到能力桶；
- 进度怎么算；
- 最多同时有几个目标；
- 目标“完成”和“放弃”由谁来判断。

### F4：收件箱和事件叫醒

- 收件箱：总控留言的列表，有已读和未读，侧边栏显示小红点。“写入收件箱”是总控的内部工具，不需要学生确认。
- 事件叫醒：签到成功、写了心得、能力晋级、活动开始前一天、每日例行检查，由 RabbitMQ 消息触发一轮总控运行。
- 防打扰：每天最多留几条；同一件事不重复说。

**要和你讨论的：**
- 哪些事件要叫醒总控；
- 每天最多留几条；
- 学生能不能关掉主动留言。

### F5：评测和观测

- 总控评测集：给定学生状态和一句话，检查总控是否调用了该调的工具、有没有乱用写入类工具。
- 差评（对总控回复点“不好”）转成评测候选，复用 B4 的流程。
- 运维面板：每个工具的调用次数、失败率、平均耗时。

**要和你讨论的：**
- 评测看什么指标；
- 是否需要人工抽查对话。

## 不在这个方向里的

- 教练的定位调整：以后单独讨论。
- 学生改了心得但能力分不更新的坑：这是现有功能的 bug，作为单独的待办修，不放进总控。
- 企业端功能：学生端定下来以后再讨论。
