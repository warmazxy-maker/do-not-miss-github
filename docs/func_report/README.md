# func_report · 功能实现报告

每完成一个功能，就在这里留一份“它是怎么实现的”报告。目的不是记流水账，而是借每一次和 AI 的协作，把背后的设计判断沉淀成自己的能力。

## 写法约定

每份报告尽量按架构师视角回答这几件事：

1. **它在系统里的位置**：属于写链路还是读链路，上下游是谁。
2. **关键决策**：每个决策写清楚问题、备选方案、最终选择和代价。
3. **一次请求的完整路径**：从点击到数据库再回来。
4. **怎么证明它是对的**：测试覆盖了什么，还有什么没覆盖。
5. **已知边界与后续**：有意没做的部分和技术债。
6. **可迁移的模式**：换个项目还能用的思路，以及面试时怎么讲。

报告里常用的技术名词，见 [术语表.md](术语表.md)。
