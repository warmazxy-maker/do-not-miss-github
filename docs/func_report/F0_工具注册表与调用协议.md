## 一、用大白话说，这次做了什么

方向 F 要做一个“总控 Agent”：它能看到平台的各项功能，和学生一起朝着目标前进。要做到这一点，先得让模型能**自己决定去查什么**，比如学生问“我下周有什么安排”，模型自己想到去查日程，查完再回答。

F0 就是这个能力的地基，学生还看不到新页面。做了五样东西：

| 东西 | 作用 |
|---|---|
| 工具注册表 | 所有工具在一个地方登记：名字、描述、参数、风险、权限、限流、超时 |
| Agent 注册表 | 每个 Agent 登记自己能用哪些工具、每轮最多几步、提示词版本 |
| 调用协议 + 执行器 | 统一的“调用请求 / 调用结果”格式；执行前做结构检查，出错一律如实返回 |
| Agent 循环 | 问模型 → 执行工具 → 把结果交回模型 → 直到它回答；有步数和时间上限 |
| 第一批 5 个只读工具 | 查预约、查日程、查能力档案、查挑战、查成长记录 |

另外运维面板多了两个分区：**工具**（只读展示两张注册表）和**调试台**（用某个用户的真实数据试跑 Agent）。

## 二、整体结构

```
学生的一句话
    │
    ▼
AgentLoop（一轮对话）
    ├─ 问模型（带上这个 Agent 能用的工具清单）──► OpenAiCompatibleLlmClient.chatWithTools
    │       模型回答文字 → 结束
    │       模型要调工具 ↓
    ├─ ToolExecutor（执行这一轮的所有调用）
    │       ① 工具存在、在 Agent 白名单里、没被关闭
    │       ② 参数符合 Schema（ToolSchemas）
    │       ③ 这个用户有权限（D1 的角色表）
    │       ④ 需确认的写入 → 拒绝（F2 才开放）
    │       ⑤ 工具自己的限流档（D4）
    │       ⑥ 执行，带超时；只读工具并行
    │       任何一步失败 → 变成一个结果（出错 / 被拒绝），不抛异常
    ├─ 把结果交回模型，进入下一轮
    └─ 每一轮、每次工具调用都记进 Agent 运行记录（步骤 + 完整产物）
```

代码位置：

| 包 | 内容 |
|---|---|
| `agentkit` | 协议（`ToolDefinition`、`ToolRisk`、`ToolCaller`、`ToolCallRequest`、`ToolResult`）、`ToolSchemas`、两个注册表、`ToolExecutor`、`AgentLoop`、`ToolOutput` |
| `agentkit/tools` | 第一批 5 个工具 |
| `master` | `MasterAgentSpec`：总控的骨架，F1 再充实 |
| `ai` | `ToolChat`（消息格式）和 `OpenAiCompatibleLlmClient.chatWithTools` |
| `ops` | `OpsAgentToolController`：工具分区和调试台的接口 |

## 三、关键决策

### 决策 1：工具定义写在代码里，不建数据库表

每个工具是一个 Java 类，类里写好自己的定义：

```java
new ToolDefinition(
    "get_schedule", 1, "查日程",
    "查询学生日程表在一个日期范围内的安排……",   // 给模型看的描述
    ToolParams.DATE_RANGE,                        // 参数的 JSON Schema
    ToolRisk.readOnly(),                          // 风险
    Permission.STUDENT_FEATURES,                  // 权限
    null,                                         // 限流档（不调模型，不另外收费）
    ToolDefinition.DEFAULT_TIMEOUT);              // 15 秒
```

启动时 Spring 把所有工具收集进 `ToolRegistry`，并做检查：名字不能重复、Schema 不能用不支持的写法、调用模型的工具必须有限流档……**任何一条不对，后端直接启动失败**，和迁移脚本写错时一样。这样错误在开发时就能发现，而不是等某个学生触发时才暴露。

为什么不放数据库：如果描述和参数存在表里，代码存在另一处，两边迟早会对不上。比如表里改了参数名，代码没跟着改，模型就会按新参数名调用，结果直到运行时才出错。

唯一能在运行时调的开关是 `.env` 里的 `AGENT_DISABLED_TOOLS`：写上工具名、重启后端，这个工具就关掉了。被关掉的工具不会出现在给模型的工具清单里。

### 决策 2：由 Agent 登记它能用哪些工具

```java
public List<String> toolNames() {
    return List.of("list_reservations", "get_schedule", "get_capability_profile",
            "list_challenges", "get_achievement_history");
}
```

一个工具可以被多个 Agent 使用；新加 Agent 时不用改任何工具。`AgentRegistry` 启动时检查：Agent 列出的工具必须都存在，每轮步数在 1～10 之间。运维面板两个方向都能查：这个 Agent 能用什么、这个工具被谁用。

### 决策 3：风险是“维度”，不是单一等级

```java
record ToolRisk(DataEffect dataEffect, ModelUsage modelUsage)
```

| 维度 | 取值 |
|---|---|
| 数据 | 只读 / 需确认的写入 / 内部写入 |
| 模型 | 不调用模型 / 会调用模型 |

以后要加新维度（比如“涉及隐私”），只需要在这个 record 里加一个字段，再在 `dimensions()` 里加一行。运维面板读的是 `dimensions()`，不用改页面。

### 决策 4：用户 ID 永远不是工具参数

```java
record ToolCaller(String userId, String agentName, Long runId)   // 系统填，模型碰不到
```

模型只能传 Schema 里定义的参数。Schema 一律写了 `additionalProperties: false`，模型如果自作主张传一个 `userId`，会得到“不认识的参数 userId”（单测覆盖了这种情况）。

### 决策 5：Java 只做结构检查

执行前只检查：工具在不在、参数格式对不对、有没有权限、限流够不够。**调哪个工具、参数是什么意思，全部交给模型。**这和“不用 Java 关键词规则替模型做语义判断”的原则一致。

参数校验用的是自己写的一个小型 JSON Schema 校验器（`ToolSchemas`），只支持工具参数用得到的那几种写法，没有新增依赖。它在启动时会拒绝用了“不认识的写法”的 Schema，防止某个工具以为自己有校验、实际上校验根本没执行。

### 决策 6：出错必须如实说，而且由系统保证

模型可能会把错误“圆”过去，比如工具出错了，它还回答“一切正常”。所以诚实不能只靠提示词：

- 工具出错、被拒绝、被截断时，`AgentLoop` 会把一句平常话放进 `notices`，**不管模型怎么回答，这句话都会显示给学生**。单测里专门测了“模型说一切正常，提示仍然在”。
- 模型本身连不上时，直接回答“抱歉，这次没能完成：AI 模型暂时连不上（请求超时）。你稍后再试一次。”，不会悄悄退回规则模式。
- 给学生看的原因里不带中转站地址和响应内容，只说“请求超时 / 模型服务返回错误 502 / 网络错误”。

### 决策 7：返回结果只裁剪字段，不删内容

| 情况 | 做法 |
|---|---|
| 有边界的数据（当前预约、能力档案） | 全部返回 |
| 没有边界的数据（日程、成长记录） | 参数里**必须**带日期范围；学生没说清楚时，模型先问 |
| 无用字段 | 每个工具自己去掉，比如预约里的**签到凭证**（这是凭证，绝不能给模型）、活动正文、内部 ID |
| 特别长的文字 | 超过 2000 字截断，并标上“（后面省略）” |
| 安全上限 | 一次最多 100 条；触发时结果里写明“只返回了前 100 条，一共 M 条”，模型必须转告，学生也会看到提示 |

### 决策 8：一轮对话的上限

| 上限 | 数值 | 到了怎么办 |
|---|---|---|
| 工具轮数 | 每个 Agent 自己定，总控是 6 | 再问一次模型，这次不给工具，让它用手上的信息回答，并提示学生“查了 6 轮先停下了” |
| 单个工具 | 15 秒（会调模型的 30 秒） | 这次调用算出错，告诉模型和学生 |
| 一整轮 | 60 秒 | 停下，告诉学生“处理时间太长” |
| 限流 | 新档位“Agent 对话”：每分钟 5 次、每天 60 次，并受 AI 并发闸约束 | 返回 429 |

同一轮里的只读工具并行执行。工具线程用的是 Java 21 的虚拟线程；共用一个线程池，而不是每次新建再关闭，因为关闭会等待一个已经超时、却不响应中断的工具，超时也就失效了。

## 四、第一批工具

| 工具 | 参数 | 返回 | 去掉的字段 |
|---|---|---|---|
| 查预约 `list_reservations` | 无 | 全部有效预约 | 签到凭证、活动正文、发布者 ID |
| 查日程 `get_schedule` | from、to（必填） | 范围内的安排 | 创建、更新时间 |
| 查能力档案 `get_capability_profile` | 无 | 全部能力桶 | 无（描述截断到 2000 字） |
| 查挑战 `list_challenges` | status（必填） | 该状态的全部挑战 | 无 |
| 查成长记录 `get_achievement_history` | from、to（必填，按完成时间） | 范围内的经历和心得 | 活动正文、地点、来源 ID |

每个工具都只调用现有的服务方法，**没有改动任何现有功能**。

## 五、验证

### 单测（新增 28 个，全量 267 个全部通过）

| 测试 | 覆盖 |
|---|---|
| `ToolSchemasTest` | 不支持的写法在启动时被拒；缺参数、类型错、日期格式错、超范围、多余参数都给出中文原因 |
| `ToolRegistryTest` | 重名、名字格式、坏 Schema、调模型却没限流档都会让启动失败；关闭开关生效；Agent 列出不存在的工具会失败 |
| `ToolExecutorTest` | 白名单外和已关闭的工具被拒；参数错可以改正后重试；没权限被拒；需确认的写入被拒；超时、异常、服务报错都如实返回；限流生效；只读工具并行且保持顺序 |
| `AgentLoopTest` | 正常调工具后回答；工具出错时提示一定在；步数用完先回答；模型连不上时道歉；60 秒超时 |
| `ToolChatParsingTest` | 按实验中真实响应的格式解析并行调用、普通回答，空响应会报错 |
| `ToolOutputTest` | 有边界的数据全量返回；安全上限一定会说明；长文字截断；日期范围包含两端 |

### 真实启动（端口 8081，真实模型 `deepseek-v4.1-flash`，学生 `student_2b3c` 的数据）

| 学生说 | 模型做了什么 | 结果 |
|---|---|---|
| 我下周有哪些安排？ | 自己换算出 11-16～11-22，调用查日程 | 如实回答没有安排 ✓ |
| 我现在哪方面能力最弱？ | 调用查能力档案 | 档案为空，说明还没法判断，并建议先写心得 ✓ |
| 我现在预约了哪些活动？ | 调用查预约 | 正确列出 RAG 读书会；返回给模型的数据里没有签到凭证 ✓ |
| 你好，今天有点累 | 不调用工具 | 安慰 ✓ |
| 帮我把 Spring Boot 工作坊加到日程里 | 同时调用查预约和查日程（并行） | 发现没预约这个活动，并说明自己现在只能查看 ✓ |
| （以组织账号的数据）我预约了哪些活动？ | 调用查预约 → 被拒绝 | 学生端出现“没有权限使用「查预约」”的提示 ✓ |

每轮耗时 7～15 秒，工具本身只要几十到两百毫秒，时间几乎都花在模型上。学生直接访问工具分区返回 404：运维面板对没有权限的人一律显示“页面不存在”，不暴露入口，这是原有设计。

**发现并修复的问题**：模型在回答里提到了工具的英文名（“看看你当前还有哪些有效预约（`list_reservations`）”）。已在通用规则里加上“不要对学生提工具的英文名字或参数名”。修复后重启，又跑了一遍全部 13 项检查，都通过；这 12 次回答里都没有再出现工具名。

这一轮还碰到一次真实的降级：中转站过了 30 秒才返回，内容是一个不是 JSON 的错误页。系统按设计回答“抱歉，这次没能完成：AI 模型暂时连不上……”，没有编造。但原因写成“网络错误”不准确，已改为“模型服务返回了无法识别的内容”（PROBLEM_LOG 第 073 条）。

## 六、留给后面阶段的

- **F1**：总控自己的页面、记忆和会话；提示词正式评审；工具描述可能还要根据实际对话调整。
- **F2**：需确认的写入。现在执行器遇到这类工具一律拒绝，F2 改成“生成待确认卡片”。
- 现在的工具结果直接放进对话。对话变长后，旧的工具结果要压缩，这在 F1 讨论记忆时一起处理。
- 调试台的运行记在管理员名下，所以那个学生自己的运行记录里看不到。

## 七、你来验收：运维面板的两个新分区

我本来想在浏览器里打开这两个分区看一眼。但运维面板要用 admin_zero 登录，而“把管理员登录凭证写进临时文件交给浏览器”的操作被权限审核拦下了，所以页面这一步留给你。后端接口都已经用脚本验证过。

1. 重启后端（新代码），启动前端，用 admin_zero 登录，进入运维面板。
2. **工具**分区：
   - 上面的表有一个 Agent“总控（master）”，能用 5 个工具，每轮最多 6 步，限流档 `AGENT_TURN`；
   - 下面的表有 5 个工具，风险都是“数据：只读”“模型：不调用模型”，状态都是“启用”，“被谁使用”都是 master；
   - 点一行能展开，看到给模型的描述和参数。
3. **调试台**分区：
   - 用户名填 `student_2b3c`（在 `test-accounts.local` 里），点示例“我下周有哪些安排？”，再点运行；
   - 等十秒左右，应该看到：回答、“工具调用”里有“查日程”和换算好的日期、状态“成功”；点开能看到给模型的数据；
   - 点“查看运行记录 #N”，会跳到“Agent 运行”分区，类型是 `AGENT_PLAYGROUND`；
   - 再把用户名换成组织账号（比如 `aiclub_2b3c`），问“我预约了哪些活动？”：工具状态是“被拒绝”，回答上方有黄色提示“没有权限使用「查预约」”。
4. **限流**分区：今天的拒绝统计里可以出现“Agent 对话”（一分钟内连点 6 次运行就能触发）。
