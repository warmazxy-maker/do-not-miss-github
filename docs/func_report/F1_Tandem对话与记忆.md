## 一、用大白话说，这次做了什么

F0 给了总控“自己决定去查什么”的能力，F1 让学生真正能用上它。总控在学生面前的名字叫 **Tandem**（双人自行车：你和它一起往前骑，方向由你定），代码里仍然叫 master。

| 东西 | 学生看到的 |
|---|---|
| Tandem 页面 | 侧边栏最上面的“伙伴 → Tandem”；一条长对话，可以翻看更早的消息 |
| 实时进度清单 | 发出问题后，Tandem 每决定查一样东西，清单就多一行“搜活动 ‘…’”，查完打勾或标红 |
| 回答下的小标签 | “查了 2 项：查日程、查能力档案”，点开能看到查了什么范围、查到几条，不显示原始数据 |
| 黄色提示 | 某一步失败、被拒绝、被截断时，不管 Tandem 怎么说，都会显示 |
| “Tandem 记住的事” | 右侧列表：它记住的关键事实，每条都能删；过期的单独折叠 |
| 清空对话 | 删掉对话和摘要，记住的事不受影响 |

另外：
- 新增 6 个工具：记住、忘掉、搜活动、看活动详情、查关注的组织、查偏好画像。Tandem 现在共有 11 个工具。
- 运维面板的调试台改成**只读**：不会写入记忆，也不会调用会留下记录的工具。

## 二、整体结构

```
学生发一句话 ──► POST /api/tandem/chat（SSE）
                    │  先扣限流、占一个 AI 名额（失败就是普通的 429）
                    ▼
               TandemService.turn（虚拟线程）
                    ├─ 保存学生的消息
                    ├─ 拼历史：
                    │     【长期记忆】（有效的，带编号）
                    │     【之前的对话摘要】
                    │     最近的消息；Tandem 的旧回答前面加一行“系统记录：你调用了 查日程（11/16～11/22）→ 0 个安排”
                    ├─ AgentLoop.run(…, Listener) ──► 每一步回调 ──► SSE 推 "step" 事件
                    ├─ 保存 Tandem 的回答（回答、步骤摘要、提示）
                    ├─ SSE 推 "reply"
                    └─ 后台：对话太长就压缩
```

| 位置 | 内容 |
|---|---|
| `master/` | `TandemController`、`TandemService`、三张表的实体和仓库、`RememberTool`、`ForgetTool`、`MasterAgentSpec`（提示词 `tandem-f1-v1`） |
| `agentkit/tools/` | 新增 `SearchEventsTool`、`GetEventDetailTool`、`ListFollowsTool`、`GetPreferenceProfileTool` |
| `agentkit/` | `AgentLoop.Listener`（进度回调）；`AgentTool.describe`（进度清单里的简短说明）；`ToolCaller.readOnly`（只读运行） |
| 迁移 | `V35__tandem_conversation.sql`：`tandem_messages`、`tandem_conversations`、`tandem_memories` |
| 前端 | `views/StudentTandemView.vue`、`api/tandem.ts`、`api/client.ts` 的 `apiStream`（读 SSE） |

## 三、关键决策

### 决策 1：一条长对话，四层记忆

| 层 | 存在哪 | 怎么进到模型眼前 |
|---|---|---|
| 对话原文 | `tandem_messages` | 页面翻看用；模型只看最近的 |
| 工作记忆 | 最近的消息加 `tandem_conversations.summary` | 每轮都带上 |
| 长期记忆 | `tandem_memories` | 每轮都把全部有效记忆放在最前面，带编号 |
| 背景 | B3 的偏好画像 | 需要时用“查偏好画像”工具读 |

**压缩**：没压缩过的消息超过 24 条或 8000 字时，后台把除最近 12 条之外的全部交给模型写成摘要。模型失败就原样保留，下一轮再试。摘要里不写可以重新查到的数据，只写结论。

### 决策 2：长期记忆只存“亲口说的关键事实”

`remember` 的描述里写明了 5 类可以记的（个人情况、约束、偏好和反感、意向、约定），也写明了不能记的（活动、预约、日程、成绩、能力分、简历）。

| 规则 | 怎么保证 |
|---|---|
| 最多 50 条 | 工具里检查，满了返回“满了”，并让模型先删再记 |
| 同一件事更新原条 | 模型传 `replaces_id`；只能更新自己学生的记忆 |
| 有时效的事 | `valid_until`；过期的不再给模型，页面折叠显示 |
| 透明 | 页面列出全部记忆，学生能删；也能直接对 Tandem 说“忘掉” |

“记住”是内部写入（F0 的风险维度），不需要确认卡片。理由是：它只改 Tandem 自己的数据，而且学生随时能看到、能删。

### 决策 3：旧的工具数据不留在对话里，但 Tandem 记得自己查过

Tandem 的旧回答在历史里是这样的：

```
（系统记录：下一条回答之前，你调用了 查日程（11/16～11/22）→ 0 个安排。原始数据没有保留，需要时重新查。）
Tandem：下周没有安排。
```

你在讨论时特别强调过：要保证“模型知道自己调用过工具”，而不是前端拼出来、模型自己不知道。验证里正好碰到一个例子：第 2 轮搜活动超时，第 4 轮学生问“第一个具体是做什么的”，Tandem 回答“上次那次搜索没成功，所以其实没有第一个，抱歉让你误会了”。

### 决策 4：进度清单边做边长

`AgentLoop` 在三个时刻回调：开始思考、某个工具开始、某个工具结束。`TandemController` 把它们变成 SSE 的 `step` 事件。一轮的事件序列像这样：

```
think running 理解你的问题
t1 running 记住 “日语水平 N2”      ← 同一轮的多个工具同时出现
t1 ok      记住了：日语水平 N2
think running 整理回答
reply …
```

每个工具通过 `describe()` 提供一句简短说明，比如查日程显示“11/16～11/22”，搜活动显示需求原文。

**限流和 AI 名额在开始推送之前就扣掉**，所以被限流时返回的是普通的 429。AI 名额一直占到这一轮结束。没有用 `@RateLimited` 注解，因为注解会在方法返回时就释放名额，而这时后台还在跑。

### 决策 5：调试台改成只读

F1 有了写入类工具（记住、忘掉），调试台又是用别人的数据在跑，所以管理员的一句测试话可能被写进学生的记忆。另外，“搜活动”会以学生的名义记一次推荐曝光，会污染 B2 的统计。

现在调试台的运行一律标为只读：写入类工具和会调用模型的工具都不执行，并提示“在调试台里不执行”。

### 决策 6：其余数值

- “Agent 对话”限流：每分钟 8 次、每天 80 次。搜活动另外计入“重 AI 功能”（每分钟 3 次）。
- 搜活动的超时是 60 秒，因为推荐流水线要连着调用好几次模型（历史上 5～47 秒）。
- 一整轮的时间上限从 F0 的 60 秒放宽到 **90 秒**（见第六节，你在 2026-11-13 决定）。
- 提示词 `tandem-f1-v1`：伙伴不是老师；先弄清需求、一次只问一个问题；答完可以给一个相关的小建议，但不推销；学生说出关键事实就记，记的时候不用特意说；画像和学生说的冲突时以学生为准；只能查看不能修改；不做心理咨询，遇到情绪危机建议联系学校资源。

## 四、验证中发现并修复的问题

**搜活动超时后，被取消的推荐运行一直停在“运行中”（PROBLEM_LOG 第 074 条）**：F0 的执行器超时后会中断工具线程，而推荐流水线被中断后拿不到数据库连接，自己的运行记录就写不进去了。现在改成超时后不再等待、但不中断，工具自己跑完、正常收尾。新增了单测。#208 这条旧记录已经写坏，会一直显示“运行中”。

## 六、一轮的时间上限：已放宽到 90 秒

F0 定的是一整轮最多 60 秒。这次实测：
- 推荐流水线历史上要跑 5～47 秒，常见 15～30 秒，中转站慢的时候更久；
- 修复后那次，搜活动本身 36 秒，整轮 57 秒，离上限只差 3 秒；
- 再加上 Tandem 前后各一轮思考（各 3～10 秒），中转站一慢，搜活动就会超时。

你决定放宽：**一整轮 90 秒，搜活动单个工具 60 秒**。连接（SSE）本身的超时是 120 秒，足够覆盖。放宽之后没有再用真实模型重跑一遍搜活动。

后端现在是我用新代码在 8080 上启动的，你可以直接用；如果要换成你自己启动的，先把它关掉。

5. 告诉它一件关于你自己的事，比如“我不喜欢纯听讲的讲座”：右侧“Tandem 记住的事”会多一条，可以删掉。

7. 运维面板的调试台：问“帮我找点活动”，“搜活动”这一步显示“在调试台里不执行”。

### 浏览器验收记录（2026-11-13）

用 `student_2b3c` 登录，走了第 1～4 步：
- 欢迎语、侧边栏入口正常；
- 发出问题后，进度清单边做边长（“理解你的问题” → “查日程 11/16～11/22 ✓” → “查能力档案 ✓” → “整理回答”）；
- 回答下的“查了 2 项”能展开；
- 回答接上了上一轮的话题。

发现并修复了三处页面问题：
1. **回答气泡被挤成很窄的一列**：教练页的消息是横向排列的，Tandem 的提示、气泡、“查了几项”成了并排的三列。改为一条消息内竖向排列。
2. **对话栏太窄**：浏览器窗格 1024 像素宽时，两栏并排，对话只剩 360 像素。Tandem 的记忆栏固定在 260～300 像素，屏幕宽度在 1180 像素以下时改为上下排列；气泡最大宽度从 82% 放宽到 92%。
3. **进度里日期显示了两遍**：工具的一句话总结不再重复日期范围。

第 5～6 步（删除记忆、清空对话）要在浏览器的确认框里点确定，自动化工具点不了，所以没在页面上点；接口已经在第五节的脚本里验证过。
